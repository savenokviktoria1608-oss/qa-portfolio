# Баг-репорты · PayFlow API

Оформление - по шаблону из `templates/bug-report.md`. Ниже разобранный пример; остальные
находки по этому стенду веду в том же формате.

---

**ID:** BUG-PAY-01
**Краткое описание:** Повтор запроса с тем же Idempotency-Key создаёт второй платёж и списывает деньги дважды

**Окружение:** стенд «PayFlow API» (bugrank.gripe), встроенная консоль запросов

**Предусловия:** получен действующий токен, зафиксирован баланс через GET /balance

**Шаги воспроизведения:**
1. Выполнить POST /payments с заголовком `Idempotency-Key: key-001` и телом `{"amount": 1999, "currency": "USD", "card_number": "4242424242424242"}`
2. Записать id созданного платежа и ответ
3. Повторить тот же запрос с тем же заголовком и тем же телом
4. Выполнить GET /payments и GET /balance

**Фактический результат:** второй запрос вернул 201 и платёж с новым id. В списке два платежа, с баланса списано дважды

**Ожидаемый результат:** второй запрос возвращает ранее созданный платёж с тем же id, новый платёж не создаётся, повторного списания нет

**Критичность:** blocker
**Приоритет:** high
**Обоснование:** повторная отправка при обрыве связи приводит к двойному списанию - прямой денежный ущерб клиенту

**Воспроизводимость:** 100%

**Вложения:** оба запроса с заголовками, оба ответа, баланс до и после
